Analyse des corrélations et des méthodes de sélection de features

1. Objectif

Sélectionner un petit ensemble de features syn_, cls_, tda_ qui reste performant et peu redondant.

2. Heatmap Spearman des 58 features

3. Explication des méthodes

Ces méthodes sont des baselines classiques de sélection de variables: filtres par corrélation, clustering de features, sélection par graphe, VIF-like, mRMR, et combinaisons supervisées avec Mutual Information. Les critères utilisés sont explicités dans les cartes ci-dessous.

greedy_spearman

Idée: on trie les features par importance vis-à-vis du label, puis on les ajoute une par une.

Règle: une feature candidate est rejetée si |rho_s(candidate, selected)| >= threshold.

Hyperparamètre: threshold. Plus il est bas, plus la sélection est sévère et compacte.

Exemple: si deux distances TDA racontent presque la même chose, on garde celle qui aide le plus le label.

greedy_pearson

Idée: même logique greedy, mais la redondance est mesurée avec Pearson.

Formule: Pearson mesure la corrélation linéaire cov(x,y)/(std(x)std(y)).

Hyperparamètre: threshold. Un seuil élevé garde plus de features.

Limite: si la relation est monotone mais non linéaire, Pearson peut moins bien la voir.

greedy_kendall

Idée: version greedy avec Kendall, une corrélation basée sur l'ordre des valeurs.

Formule: Kendall compare les paires concordantes et discordantes: tau=(C-D)/(C+D).

Intérêt: robuste au bruit et aux valeurs extrêmes.

Hyperparamètre: threshold.

Lecture: bonne méthode si on veut supprimer les doublons sans trop dépendre de la forme exacte des données.

greedy_nmi

Idée: remplacer la corrélation classique par une dépendance informationnelle.

Formule: NMI normalise l’information mutuelle: I(X;Y)/normalisation(H(X),H(Y)).

Ce que ça détecte: des relations non linéaires entre features.

Hyperparamètres: threshold et n_bins, car les valeurs continues sont discrétisées.

Limite: le résultat peut dépendre du choix du nombre de bins.

cluster_spearman

Idée: construire des groupes de features fortement corrélées entre elles.

Règle: on forme des clusters avec une distance 1-|rho_s|, puis on garde une représentante par cluster.

Hyperparamètre: threshold, qui contrôle la formation des groupes.

Exemple: plusieurs variantes cosine/jaccard peuvent former un même cluster syntaxique.

graph_independent_spearman

Idée: chaque feature est un noeud; une arête relie deux features trop corrélées.

Formule: arête si |rho_s(feature_i,feature_j)| >= threshold; on cherche un ensemble indépendant.

Hyperparamètre: threshold, qui décide quand deux features sont incompatibles.

Lecture: méthode très intuitive pour justifier visuellement pourquoi une feature est supprimée.

iterative_vif_like

Idée: supprimer les features qui peuvent être reconstruites par combinaison des autres.

Formule: VIF_j = 1/(1-R_j²), où R_j² vient de la régression de la feature j sur les autres features.

Hyperparamètre: threshold VIF-like. Plus il est petit, plus on supprime.

Important: cette méthode n'a pas de k; elle choisit le nombre final automatiquement.

mrmr_spearman

Nom: mRMR = maximum relevance, minimum redundancy.

Critère mRMR utilisé: score(f) = relevance(f, y) - penalty × mean_redundancy(f, S), avec S les features déjà gardées.

Dans le code: relevance(f,y)=MI(f;y) et mean_redundancy(f,S)=moyenne(|rho_s(f,s)|) pour s dans S.

Hyperparamètres: k fixe le nombre de features; penalty contrôle à quel point on évite les doublons.

Exemple: si syn_jaro_winkler est très utile mais que syn_jaro raconte presque la même chose, mRMR peut garder seulement l’un des deux pour laisser de la place à une feature TDA ou CLS différente.

family_aware_spearman

Idée: éviter qu'une famille domine toute la sélection.

Familles: syn syntaxique, cls classique/statistique, tda topologique.

Hyperparamètres: family_threshold contrôle la redondance dans une famille; global_threshold contrôle la redondance entre familles.

Lecture: méthode intéressante si on veut une sélection interprétable et équilibrée.

combo_mi_prefilter_mrmr

Idée: d'abord garder un grand sous-ensemble de features importantes, puis appliquer mRMR.

Étape 1: prefilter garde les features avec forte I(feature; label), donc informatives pour match/non-match.

Étape 2: k et penalty choisissent une sélection finale moins redondante.

Intérêt: réduire l'espace de recherche avant une sélection plus fine.

combo_cluster_then_mrmr

Idée: supprimer d'abord les doublons évidents par clustering, puis utiliser mRMR.

Hyperparamètres: cluster_threshold, k, penalty.

Intérêt: combiner une étape très interprétable avec une étape supervisée.

Lecture: bon compromis quand il y a beaucoup de features très similaires.

combo_family_then_mrmr

Idée: équilibrer d'abord les familles, puis choisir les meilleures features avec mRMR.

Hyperparamètres: family_threshold, global_threshold, k, penalty.

Intérêt: garder une diversité syn/cls/tda tout en optimisant le F1.

Lecture: méthode défendable pour comprendre la contribution de chaque famille.

combo_mrmr_then_graph

Idée: mRMR propose d'abord des features pertinentes, puis le graphe supprime les redondances restantes.

Hyperparamètres: k, mrmr_prefilter, graph_threshold.

Intérêt: partir d'une sélection supervisée, puis la nettoyer visuellement.

Lecture: pratique pour expliquer les suppressions avec un graphe de corrélation.

combo_mi_prefilter_graph

Idée: préfiltrer par I(feature; label), puis choisir un ensemble peu corrélé avec le graphe.

Hyperparamètres: prefilter, k, graph_threshold.

Intérêt: obtenir une sélection compacte, informative et facile à visualiser.

Lecture: utile si l'objectif principal est de produire un graphe clair et défendable.

6. Conclusion

Il y a beaucoup de méthodes, mais elles tournent presque toutes autour de la même idée: garder des features utiles, et supprimer les features qui racontent la même chose.

On peut les comprendre en quatre familles.

1. Méthodes qui suppriment les doublons. greedy_spearman, greedy_pearson, greedy_kendall et greedy_nmi prennent les features une par une. Si une nouvelle feature est trop corrélée avec une feature déjà gardée, elle est supprimée.

La différence entre elles est seulement la manière de mesurer “trop similaire”: pearson mesure une similarité linéaire, spearman une similarité de rang, kendall une similarité de rang plus robuste, et nmi une dépendance non linéaire.

Exemple: si syn_jaro et syn_jaro_winkler donnent presque la même information, on en garde une seule.

2. Méthodes qui font des groupes. cluster_spearman regroupe les features très corrélées entre elles, puis garde une représentante par groupe.

Exemple: un groupe peut contenir syn_jaro, syn_jaro_winkler et syn_lcs_ratio. La méthode évite de garder toutes ces features si elles décrivent le même signal.

3. Méthodes qui construisent un graphe. graph_independent_spearman représente chaque feature comme un noeud. Deux features très corrélées sont reliées par un lien. La méthode cherche alors à garder des features qui ne sont pas trop connectées entre elles.

Exemple: si syn_jaro et syn_jaro_winkler sont reliées par une forte corrélation, on évite de garder les deux.

4. Méthodes qui cherchent un compromis entre utilité et redondance. mrmr_spearman signifie maximum relevance, minimum redundancy. Elle garde des features utiles pour prédire match/non-match, mais évite de garder plusieurs features qui portent la même information.

Le critère utilisé est: score(f)=MI(f;y)-penalty×mean(|rho_s(f,S)|). Ici, MI(f;y) mesure l'information entre la feature et le label, et mean(|rho_s(f,S)|) mesure la redondance moyenne avec les features déjà sélectionnées.

Les méthodes combo_* sont des pipelines en deux étapes. Par exemple, combo_mi_prefilter_mrmr garde d'abord les features les plus informatives avec la Mutual Information, puis applique mRMR. combo_cluster_then_mrmr fait d'abord des clusters, puis applique mRMR. combo_family_then_mrmr équilibre d'abord les familles syn, cls et tda, puis applique mRMR. combo_mrmr_then_graph applique d'abord mRMR, puis nettoie encore avec un graphe de corrélation.

La phrase simple à retenir est: j'ai testé plusieurs stratégies de sélection de features. Certaines suppriment directement les features corrélées, certaines groupent les features similaires, certaines utilisent un graphe de corrélation, et d'autres comme mRMR cherchent un compromis entre importance pour le label et faible redondance. Ensuite, j'ai comparé ces méthodes avec le même protocole F1.
